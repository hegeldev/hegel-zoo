- **batch-01.json**: Both targets have every bug record already attributed directly to a Hegel property, so no attributions were needed. Shape worth noting: in go/apd, 17 of 34 properties are per-bug narrowed properties (comments start with 'apd/N:', names describe the correct behaviour, inputs are constrained to the failing region) and the README itself calls them 'pinned'; I tagged all of them pin. Each bug's bugs_direct points at its own narrowed property, so a naive direct-attribution count would say 17 general properties found nothing and 17 pins found one each, whereas the README makes clear the broad Python-oracle properties are what surfaced most divergences (they now Assume/skip around the pinned cases, e.g. apd/2 and apd/3 in TestHegelSetStringAgreesWithPythonDecimal). In go/bbolt the README states both bugs 'came from reading Bucket.MoveBucket and were confirmed with a probe before the properties were written', so the two pin-tagged properties reproduce rather than discovered the bugs; the direct attribution should be read with that in mind. Rubric gaps: (1) 'a valid computation must raise a documented condition flag / error on overflow' (apd/7) sits between rejection and spec-postcondition; (2) 'helpers' bundle properties (TestHegelDecimalHelpersAgreeWithTheModel, TestHegelConversionsAgreeWithStrconv, TestHegelTextFormatsAgreeWithTheModel) mix model, round trip and postcondition checks and the category depends heavily on which check is read as leading; (3) aliasing independence (result pointer == operand pointer) is a recurring Go shape that fits internal-consistency only loosely. The Python decimal child-process oracle and the model-of-a-B+tree driver are both conventional in design and were not tagged interesting at the property level.

Several bubbles 'models' lean on library internals (the textarea wrap grid, the textinput window offsets, the library's own window arithmetic in filepicker/tree), so model-oracle vs internal-consistency is blurry there.
