# fastutil

[vigna/fastutil](https://github.com/vigna/fastutil): type-specific collections for Java - the
primitive hash maps and sets (open addressing, linked, custom-strategy, big), the AVL and red-black
tree maps and sets, array maps and sets, array lists and big lists, priority queues (direct,
indirect and semi-indirect), the static sorting and searching utilities of `IntArrays`,
`DoubleArrays`, `IntBigArrays` and `BigArrays`, and the iterator, spliterator, wrapper and singleton
helpers. Pinned at the 8.5.19 release tag (46316b12, 2026-07-22). Apache-2.0; README, CHANGES and
TODO say nothing about AI contributions and there is no CONTRIBUTING (the release commit itself is
"Round of fixes by Fable").

The checkout's Java sources are generated by make from `drv/` templates and built with Ant, a long
build, so `[run] setup = []` builds nothing: the Maven module `hegel/` the patch adds at the
repository root depends on the `it.unimi.dsi:fastutil:8.5.19` jar Maven Central published from this
very tag (its `fastutil.version` must move with `base.version` on a bump), on `dev.hegel:hegel` and
on JUnit 5. `Zoo.java` (`run(name, body)` wraps `Hegel.test`; with `ZOO_COLLECT=1` it prints one line
per distinct failure message and the `count()` statistics; `throwsClass`/`outOfBounds` classify
exceptions), the judge's `ZooListener`, and the tests live in `hegel/src/test/java/zoo/`. See
HACKING.md for the Java mechanics.

## What is tested

Script-driven differential tests: each case builds a random fastutil structure and a `java.util`
model, applies a random script of mutators through both (primitive and boxed entry points, views and
iterators included) and compares the observable state after every step, then the bulk readers
(equality and hash codes both ways, iteration order where it is defined, copies and clones, streams
and spliterators, sorted views). Known bugs are gated on their exact symptom with
`count("known fastutil/N")` and the model resynchronized.

- **MapsTest** - *mapsMatchTheJavaUtilModel*: `Int2IntOpenHashMap` (random capacity and load
  factor), `Int2IntLinkedOpenHashMap`, `Int2IntOpenCustomHashMap`, `Int2IntAVLTreeMap`,
  `Int2IntRBTreeMap` and `Int2IntArrayMap` against `TreeMap` or `LinkedHashMap`, with a random
  default return value: put/remove/putIfAbsent/replace/remove(k, v)/merge/compute*/addTo, boxed
  variants including null-returning remapping functions, `putAll`, removal and `removeIf` through the
  key, value and entry views, iterator removal, clear/trim, the linked map's move-to-first/last and
  removeFirst/Last operations; per step get/containsKey/containsValue/getOrDefault; then entries and
  fast iteration, forEach, equals/hashCode (map and views), streams, clone, and for the sorted maps
  first/last, head/tail/subMap over the bounds and `keySet().iterator(from)` both ways.
- **SetsTest** - *setsMatchTheJavaUtilModel*: `IntOpenHashSet`, `IntLinkedOpenHashSet`,
  `IntOpenCustomHashSet`, `IntLinkedOpenCustomHashSet`, `IntOpenHashBigSet`, `IntAVLTreeSet`,
  `IntRBTreeSet` and `IntArraySet` against `LinkedHashSet`/`TreeSet`: add/remove (boxed and
  primitive), addAll/removeAll/retainAll with fastutil and `java.util` arguments, removeIf, iterator
  removal, subSet removal, removeFirst/Last, trim, move-to-first/last, copies; then the toIntArray
  variants, equals/hashCode, containsAll, streams and split spliterators, and for the sorted sets the
  views, `iterator(from)` forward and back, skip/back counts and the spliterator characteristics.
- **ListsTest** - *listsMatchTheJavaUtilModel*: `IntArrayList` (fresh and `wrap`ped) and
  `IntBigArrayBigList` (through an `AbstractIntList` adapter that delegates every operation) against
  `ArrayList`: positional add/set/remove, addElements/removeElements/getElements/setElements,
  indexOf/lastIndexOf, rem, bulk operations with fastutil and `java.util` arguments, removeIf,
  list-iterator edits, edits through `subList` views (bulk removal included, bug 1 gated),
  sort/unstableSort, size(n), trim/ensureCapacity, out-of-bounds accesses (`IndexOutOfBoundsException`
  or a subclass); then equals/hashCode/compareTo, immutable and unmodifiable copies, streams,
  spliterators, backward list iteration and nested sub-list views.
- **ArraysTest** - *sortsAgreeWithJavaUtil* (thirteen `IntArrays` sorts - quick, merge (plain and
  with a support array), stable, radix, parallel, indirect, two-array - agree with `Arrays.sort` on
  the multiset and the order, the stable ones keep ties in index order; binarySearch, reverse,
  shuffle, equals), *floatingPointSortsOrderLikeJavaUtil* (the `DoubleArrays` and `FloatArrays` sorts
  compared bit for bit with `Arrays.sort`, so -0.0/0.0 and NaN placement included; `radixSortIndirect`
  sortedness and stability by identical bit patterns, bug 3 gated; `LongArrays.radixSort` over both
  signs), *objectSortsAreStableWhereDocumented* (`ObjectArrays` merge and stable sorts are stable,
  the quick sorts order), *bigArraysSortAndSearchLikeArrays* (`IntBigArrays` quick/radix/parallel
  sorts and `BigArrays.mergeSort`, binarySearch, forceCapacity, copyFromBig, equals).
- **QueuesTest** - *priorityQueuesDequeueInOrder* (`IntHeapPriorityQueue`, `IntArrayPriorityQueue`
  and a synchronized wrapper, with and without a comparator, against `PriorityQueue`; `changed()`
  after modifying the first element; `last()` is optional), *indirectQueuesTrackTheReferenceArray*
  (the heap and array indirect queues and the semi-indirect heap against a multiset of indexes into a
  mutable reference array: enqueue, dequeue, first/last, `front()`, `changed()`/`changed(i)`/
  `allChanged()`, `remove(i)`; `contains` is optional), *fifoQueueMatchesArrayDeque*
  (`IntArrayFIFOQueue` against `ArrayDeque`).
- **UtilitiesTest** - *iteratorsAndSpliteratorsWalkTheirSequences* (`IntIterators`
  wrap/concat/fromTo/unwrap/pour/singleton/EMPTY/indexOf/any/all, list iterators both ways,
  unmodifiable; `IntSpliterators` wrap/concat/fromTo/asSpliterator/asIterator, estimateSize and skip;
  bug 2 gated for backwards ranges), *wrappersAndSingletonsKeepTheContract* (the
  `IntSets`/`IntLists`/`Int2IntMaps` singletons and EMPTY_* constants: reads, equality and hash codes
  against `java.util`, immutability, iterators (bug 4 gated); unmodifiable and synchronized sorted
  sets, lists and maps: equality, reads, sorted views, mutators throw (bug 5 gated), writes through
  the synchronized wrapper reach the base; `IntSets.fromTo/from/to`; `IntCollections.asCollection`),
  *frontCodedAndImmutableListsReadLikeTheirSource* (`IntArrayFrontCodedList` at random ratios:
  get/getArray/get(buf)/arrayLength/iterators/clone/ratio against the source arrays, the hash code
  (bug 6 gated); `IntImmutableList` construction, `of`, the `toList` collectors, equality with the
  source).
- **PinsTest** - one deterministic reproduction per bug, listed in `target.toml`'s
  `[expected_failures]`.

Conventions found while writing the tests, not bugs: the custom hash maps and sets hash their
entries with the strategy (`strategy.hashCode(key) ^ value`), so a strategy meant to agree with
`java.util` must hash like `Integer.hashCode`; `mergeSort(a, from, to, supp)` requires `supp` to hold
a copy of `a`'s range; out-of-range accesses may throw `ArrayIndexOutOfBoundsException` (a subclass
of the documented exception); `IndirectPriorityQueue.contains` and `IntPriorityQueue.last` are
optional operations; `contains(Object)`/`containsKey(Object)` with a foreign type may throw
`ClassCastException`, and `remove` of an absent element from an unmodifiable set may return false
instead of throwing (both allowed by the `java.util` contracts); `IntSets.fromTo` is documented as an
unmodifiable `IntSet`, not a sorted set; a semi-indirect queue holding an index several times must be
told `allChanged()` when that index's value changes, since `changed()` re-sifts the top alone;
`radixSortIndirect`'s postcondition is `a[perm[i]] <= a[perm[i + 1]]`, under which -0.0 and 0.0 are
equal.

Not covered: the object-keyed maps and sets beyond what the templates share with the int ones,
`Double2*`/`Object2*` maps (NaN and null keys), the I/O classes (`BinIO`, `TextIO`, the fast
streams), concurrency, and the char/short/byte/boolean/float/long/big variants beyond the few
exercised above (the templates are shared, so each bug notes its generated siblings).

## Bugs

Six at 8.5.19 (`bugs.toml`): `removeAll` through the shared `AbstractIntCollection` implementation
removes only the first occurrence of each element (sub lists) [1]; backwards `fromTo` ranges report
negative skip and estimateSize counts [2]; `radixSortIndirect(stable = true)` reorders equal NaN keys
through the quicksort fallback [3]; the singleton iterators' `skip`/`back` report a move without
moving [4]; `IntLists.unmodifiable(list).size(n)` resizes the backing list [5];
`IntArrayFrontCodedList.hashCode` is not repeatable [6].
